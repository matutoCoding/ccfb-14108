# 跳水动作分析系统

浏览器端跳水动作三维分析系统：TypeScript + three.js + Vite，全部数据存本地浏览器 IndexedDB，无后端、无任何网络上传。

## 启动

```bash
npm install
npm run dev        # 开发，默认 http://localhost:5173
npm test           # 核心算法单测（圈数/事件/修复/往返，14 项）
npm run check      # 严格 TypeScript 类型检查
npm run build      # 生产构建到 dist/
node tests/smoke.mjs   # 需先 npm run dev；用系统 Chrome 做端到端冒烟（需装 playwright-core）
```

首次打开会自动播种：2 名队员、8 个动作代码、3 堂训练课、7 跳 240Hz 合成动捕（其中 1 跳注入了丢帧 + 关节翻转）。

## 六个页面

| 页面 | 能力 |
|---|---|
| 队员档案 | 身高/臂展/体重，蒙皮人体按这些尺寸等比缩放 |
| 动作库 | 按代码（107B、5253B…）归档，挂难度系数 DD，支持自动估算 |
| 训练课 | 按日期串起当天每一跳；生成合成数据或导入 BVH/CSV；入水角历次散点趋势 |
| 三维回放 | 0.1×/0.25×/0.5×/1× 慢放、逐帧、四机位、时间轴、实时指标、标注、分析单 |
| 对比分析 | 两跳按离板帧对齐，实虚叠加或左右分屏同步播，自动定位关节角度差最大段 |
| 设置 | 关节阈值、采样率、厂商骨骼命名映射、本地数据备份/清空 |

## 关键工程决策（为什么圈数和离板对齐是准的）

### 1. 圈数统计：角速度积分，而不是量身体纵轴

翻腾/转体圈数用**根姿态逐帧四元数差分 → 世界系角速度 → 按轴积分**：

- 翻腾轴 = 固定世界 Z 轴（侧向翻腾轴）
- 转体轴 = 帧间**中点姿态**的根坐标系 Y 轴（旋转复合链法则，在增量所在的中点体坐标系分解）
- 四元数双覆盖处理：差分结果 `w<0` 时取负，保证始终走短路径（|角|≤π），方向连续

这样团身、屈体改变身体外形不会污染圈数——测量只依赖根旋转，与关节姿态解耦。
合成数据生成器与分析器共用同一套旋转数学（`根姿态 = qSomer(φ)·qTwist(θ)`），
所以 107B 必然累计 3.5 圈翻腾 / 0 转体，5253B 必然 2.5 圈翻腾 + 1.5 转体。单测容差 0.1 圈内。

### 2. 离板/入水对齐

- 离板帧：根 Y 高于板顶 5cm 且垂直速度 >0.5 m/s 的首帧
- 入水帧：飞行段根 Y 首次下穿水面（y≤0）
- 最高点：离板—入水间质心最大高度帧
- 打开帧：最紧姿态后髋膝同时重新伸直的首帧
- 四个事件都能在时间轴上手动拖动修正，修正后持久化

### 3. 防糖纸效应

规范骨骼 24 关节，前臂/小腿各有**独立扭转骨**（LeftForeTwist、LeftCalfTwist…），
手部挂在扭转骨末端。蒙皮用**刚性绑定**（每段几何体只受一个骨骼 100% 权重，
skinIndex/skinWeight 用标准 4 分量），蒙皮本身从不做沿长轴的扭曲插值，
扭转全部由扭转骨承担——机制上消除糖纸效应。

### 4. 丢帧与关节翻转

- 丢帧：时间戳相对采样率出现断层 → 位置线性插值、旋转 SLERP 补齐，段落标黄
- 关节翻转：相邻帧某关节旋转跳变 >120° → 标记并用前后有效帧 SLERP 修复
- 修复后保留质量段落记录，时间轴黄色高亮，分析单注明

### 5. 240Hz 不顿

播放按真实墙钟时间推进、渲染取最近整数帧（帧间隔 4.17ms）。0.1× 慢放时每帧停留约 42ms，
肉眼连续；逐帧按钮精确 ±1 帧。时间轴拖动、seek 都是整数帧精确定位。

## 坐标系约定

Y 向上、+X 朝水池（跳板前方）、±Z 为左右；水面 y=0，板顶/台高为平台高度（3m / 10m）。

## 数据与隐私

所有队员、动作、训练课、动捕帧、标注、设置都在浏览器 IndexedDB（库名 `dive-analysis-db`）。
设置页可导出整库 JSON 备份、导入恢复、一键清空。分析单是自包含 HTML（关键帧截图内嵌为 dataURL），
可直接发给教练或打印。
